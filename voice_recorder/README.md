# Voice recorder

## Portable Windows app

Double-click `../dist/RU-KWS-Recorder.exe` to open the setup menu. Python is
bundled; recipients do not need to install Python, pip or dependencies.
Distribute `../dist/RU-KWS-Recorder-Windows-x64.zip`; extract it before use.
The ZIP excludes personal recordings. See [QUICKSTART.txt](QUICKSTART.txt).

Both the source and the EXE now save sessions to `../dist/recordings` in this
project. When copied elsewhere, the EXE saves in `recordings` beside itself.
The menu accepts a different output folder. An external `commands.json` beside
the EXE overrides the embedded default commands. P/R/S key positions work with
both English and Russian keyboard layouts.

Build on Windows x64 using Python 3.12 x64, from the project root:

```powershell
py -3.12 -m venv build/recorder-env
./build/recorder-env/Scripts/python.exe -m pip install -r voice_recorder/requirements-build.txt
./build/recorder-env/Scripts/python.exe voice_recorder/build_windows.py
./build/recorder-env/Scripts/python.exe voice_recorder/test_portable.py
```

The build runs the unit tests and the executable self-test, then creates the EXE,
instructions, dependency notices and a portable ZIP in `dist`. It leaves existing
recordings and external command settings intact. `requirements-build.txt` pins
the packaging environment used for this build.

Self-test checks imports (including PortAudio), resources, device enumeration,
and PCM WAV I/O without capturing microphone audio. Actual sound quality still
requires a short recording and playback on the target PC. The executable targets
Windows 10/11 x64 and is unsigned. It is not a macOS/Linux or 32-bit build.

Packaging references: [PyInstaller runtime paths](https://pyinstaller.org/en/stable/runtime-information.html),
[sounddevice installation](https://python-sounddevice.readthedocs.io/en/latest/installation.html).

# Запись реальных голосовых команд в Windows

Python 3.10+; запуск в PowerShell или Windows Terminal. Микрофон записывается только после Enter. Окно консоли должно оставаться в фокусе; клавиши не глобальные. Нажимайте клавиши коротко, не удерживайте их. Интерфейс использует латинские P/R/S: выберите английскую раскладку.

## Быстрый старт

Откройте PowerShell в этой папке:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe record.py devices
.\.venv\Scripts\python.exe record.py clips --speaker sergey --repeats 10
```

Активация окружения не требуется. Если микрофон выбран неверно, добавьте `--device 2`, заменив 2 на индекс из `devices`. Если доступ запрещён, проверьте разрешение доступа к микрофону для классических приложений в настройках конфиденциальности Windows.

По умолчанию используются шесть команд из соседнего проекта, по десять повторений в случайном порядке. Свой список можно задать через `--commands my_commands.json`: формат показан в `commands.json`, метки должны быть уникальны. Текст подсказки — ожидаемая фраза; скрипт не проверяет, что вы действительно её произнесли.

1. Прочитайте фразу; Enter начинает запись. Дождитесь надписи «ЗАПИСЬ», выдержите около 0,3–0,5 секунды и произнесите фразу.
2. Оставьте около 0,5 секунды после фразы и нажмите Enter. Через 8 секунд запись завершится автоматически; предел меняется через `--max-seconds`.
3. P прослушивает запись. Enter принимает, R начинает новый дубль той же фразы, S отклоняет и переходит к следующей. Esc завершает сбор.

При повторении/отклонении старый файл остаётся на диске с `accepted=false`, чтобы случайно не потерять дубль. Используйте **только принятые строки `manifest.jsonl`**, а не все WAV в папке. Новый запуск создаёт новую сессию, прежние записи не перезаписываются. План сохраняется в `plan.json`; автоматического продолжения незаконченной сессии нет.

Пример условий записи:

```powershell
.\.venv\Scripts\python.exe record.py clips --speaker sergey --condition kitchen_2m --repeats 10 --device 2
```

Записываются WAV mono PCM16, исходная частота микрофона, без нормализации и удаления пауз. `--rate 16000` запрашивает 16 кГц напрямую, но некоторые устройства это не поддерживают. Тогда оставьте родную частоту и преобразуйте в частоту модели качественным ресемплингом при подготовке теста. Не меняйте только заголовок WAV. При ресемплинге JSON-границы в отсчётах нужно пересчитать, а секунды сохраняются.

## Длинные записи с разметкой

```powershell
.\.venv\Scripts\python.exe record.py long --speaker sergey --condition kitchen_2m --max-seconds 1200
```

Enter начинает **одну непрерывную запись**. Пока она идёт:

- 1–6: открыть интервал для показанной команды; затем произнесите её.
- Пробел: закрыть интервал после фразы.
- Другая цифра: закрыть текущий интервал и открыть следующий.
- Enter или Esc: закончить запись; открытый интервал закроется на конце WAV.

Между отметками продолжайте обычную деятельность: говорите, двигайтесь, оставляйте тишину. Запись не останавливается. Для отрицательного теста просто не ставьте отметки, но затем обязательно проверьте, что целевые фразы не прозвучали случайно. Предел по умолчанию 30 минут, максимум одного файла — час. Длительные тесты можно собирать несколькими сессиями.

Результат находится в `recordings/<дата_идентификатор>/`:

| Файл | Содержимое |
|---|---|
| `session.json` | Диктор, условия, микрофон, частота, список команд |
| `continuous.wav` | Непрерывное аудио |
| `continuous.json` | Длительность, качество, ошибки, черновые интервалы в отсчётах |
| `labels.draft.txt` | Черновые интервалы в секундах для Audacity: начало TAB конец TAB метка |

**Нажатие клавиши — черновая подсказка, не точная разметка речи.** Реакция человека, паузы, буфер устройства и дискретность опроса примерно 20 мс вносят ошибку. Времена считаются от количества сохранённых отсчётов, поэтому вычисление не накапливает дрейф часов. Это не устраняет задержку микрофона. Щелчки клавиатуры тоже могут попасть в звук.

### Как получить окончательную разметку

1. Откройте `continuous.wav` в Audacity, импортируйте `labels.draft.txt` как метки.
2. Прослушайте **весь файл**, поправьте начало/конец каждой метки по слышимой речи и волновой форме. Начало — первый звук фразы, конец — последний; для многословной команды размечайте всю фразу, включая внутренние паузы. Добавьте пропущенные команды, удалите ошибочные метки.
3. Экспортируйте исправленные метки в `labels.reviewed.txt` в простом формате из трёх столбцов через TAB. Используйте идентификаторы `next`, `back` и т. д., а не русские названия. Не включайте расширенный экспорт с частотными строками.
4. Проверьте файл и создайте JSON для оценки:

```powershell
.\.venv\Scripts\python.exe record.py import-labels --wav recordings\SESSION\continuous.wav --labels recordings\SESSION\labels.reviewed.txt
```

Замените `SESSION` на имя папки. Результат — `continuous.reviewed.json`. Скрипт проверяет метки, конечность времён и границы WAV; статус `reviewed` означает вашу ручную проверку, не автоматическое распознавание. Интервалы `[start_frame, end_frame)` допускают перекрытия (например, два диктора). Пустой файл меток допустим для вручную проверенной отрицательной записи. Черновые данные сохраняются отдельно. При повторном импорте сначала переименуйте прежний reviewed JSON.

## План полезного длинного теста

Начальный пилот: 3–5 сессий по 10–20 минут в разных условиях. Это проверка процесса сбора, а не достаточное доказательство низкой частоты ложных срабатываний.

- **Команды в обычной обстановке.** Разная дистанция, громкость, темп, направление головы; интервалы между командами нерегулярные. Включите команды внутри предложений и повторения с короткой паузой. Сохраните естественный фон, не вырезайте промежутки.
- **Отрицательные записи.** Чтение/разговор без целевых фраз, тишина, бытовые шумы, телевизор. Отдельно похожие фразы: «Запустить музыку», «Остановить запись», «Сколько стоит», «Осталось немного». Для оценки редких ложных тревог нужны часы такого материала.
- **Другие дикторы и дни.** Используйте стабильные speaker ID. Держите тестовые сессии отдельно от обучения и подбора порога. Не нарезайте один длинный исходник в разные выборки. Если обещаете обобщение на новых людей, дикторы теста тоже должны быть отдельными.

Сначала определите, что является целью: любое произнесение ключевой фразы или только обращение к устройству. Например, «я сказал “назад”» для детектора ключевых слов обычно является положительным событием. Если нужна именно команда, добавьте отдельно ручной признак намерения; одних меток ключевых фраз недостаточно. Слова из телевизора размечайте по той же заранее принятой политике.

Оценивайте поток, передавая модели звук непрерывно, с тем же размером шага и состоянием, что на устройстве. Полезные показатели: доля обнаруженных событий по каждой команде, ложные срабатывания в час на отдельно проверенном отрицательном аудио, задержка относительно конца фразы. Заранее зафиксируйте окно сопоставления события и детекции; каждой истинной команде сопоставляйте не более одной детекции. Не считайте каждое соседнее окно независимой командой. Порог и подавление повторов настраивайте на validation, затем фиксируйте перед test.

### Можно ли склеить короткие записи?

Да, это удобный **дополнительный синтетический тест**: сначала уточните границы речи внутри каждого клипа, затем разместите клипы в фоновом аудио с известными смещениями. Итоговая метка = смещение вставки + границы речи клипа. Записывайте seed, источники, коэффициенты усиления и проверяйте отсутствие клиппинга. Выбирайте непересекающиеся интервалы вставок, если перекрытие речи не является отдельным сценарием.

Не используйте границы целого клипа как границы слова: в нём есть паузы. Склейки и постоянная громкость могут облегчить задачу модели, а реальные дальние команды и фон проходят через микрофон одновременно. Поэтому итоговый тест должен включать реальные непрерывные записи. ASR/forced alignment может ускорить черновую разметку по транскрипту, но ошибки и пропущенные слова всё равно требуют прослушивания.

## Ошибки и проверка

При переполнении входного буфера скрипт прекращает запись, сохраняет частичный WAV и поле `error`. Такие файлы нельзя включать в оценку: временная непрерывность нарушена. Ctrl+C во время записи тоже сохраняет частичный файл с ошибкой. При обычном завершении заголовок WAV корректно закрывается. Принудительное завершение процесса/отключение питания может оставить WAV без метаданных; это не принятая запись.

Проверки без микрофона:

```powershell
py -m unittest discover -s . -p "test_record.py" -v
```

Автотесты проверяют WAV, интервалы, обрезку по лимиту и ошибки потока с имитацией аудиоустройства. Работа с реальным микрофоном и качество звука проверяются вручную: запишите один дубль, прослушайте P, затем запишите минуту в длинном режиме и сверьте метки.

Документация используемых интерфейсов: [sounddevice: установка](https://python-sounddevice.readthedocs.io/en/latest/installation.html), [RawInputStream](https://python-sounddevice.readthedocs.io/en/latest/api/raw-streams.html), [импорт и экспорт меток Audacity](https://manual.audacityteam.org/man/importing_and_exporting_labels.html).
